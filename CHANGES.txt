Version 2026083100.01
- Fixed lesson previews being redirected to the login page when embedded in an iframe on a remote
  Moodle site. Core issues the session cookie as SameSite=Lax, which a browser will not send for a
  document inside a cross site iframe, so the preview rendered as a guest and then died on its
  first web service call with "servicerequireslogin" - which lib/amd/src/ajax.js turns into a
  navigation to /login/index.php. A new after_config hook callback re-issues the session cookie as
  "SameSite=None; Secure; Partitioned" for requests made in a third party context. First party
  browsing of the lesson bank is untouched. Controlled by the new "Allow lesson previews in an
  iframe" setting (on by default), and requires https. Note Safari blocks third party cookies, so
  previews there may still fail.

Version 2026083100.00
- Fixed local_lessonbank_list_minilessons failing with "Invalid response value detected" whenever
  the listing included a minilesson whose settings form had never been saved. Custom field values
  were only read when a customfield_data row existed, so such a lesson left the required "skills"
  key out of the response and took the whole web service call down with it. The field's data
  controller is now always built, which falls back to the field's configured default - the value
  the author was shown in the settings form.
- A custom field that is not set up on the site at all now reports an empty string rather than
  omitting the key, so no listing can be broken this way again.
- Fixed the skill and topic filters. Those are multiselect fields, which store their selection as
  a comma separated list of option indexes, so the old equality test only matched lessons tagged
  with that single option - a lesson tagged "Listening, Speaking" was found by neither filter.
